# Axiom
=======
# WhatsApp Forward Checker — Backend

A lightweight FastAPI backend that checks a forwarded WhatsApp/social message
against a curated database of known misinformation claims (health myths,
financial scams, and communal/political rumours), using multilingual
(English + Hindi) semantic similarity — not just exact keyword matching.

If the message closely matches a known claim, the API returns the verdict,
a plain-language explanation, and a source. If nothing matches confidently,
it returns a short self-verification checklist instead.

---

## 1. Project structure

```
backend/
├── main.py              # FastAPI app, routes, CORS, startup logic
├── models.py             # Pydantic request/response schemas
├── matching.py            # Embedding + cosine similarity matching logic
├── data/
│   └── claims.json        # Curated claims database (24 entries)
├── requirements.txt        # Pinned dependencies
└── README.md
```

---

## 2. Requirements

- Python 3.9+ (3.10/3.11 recommended)
- ~2 GB free disk space the first time you run it (the sentence-transformer
  model, ~470MB, is downloaded and cached locally on first startup)
- Internet access on first run only (to download the model from Hugging Face).
  After that, it's cached and works offline.

---

## 3. Installation

```bash
# 1. Move into the backend folder
cd backend

# 2. (Recommended) create and activate a virtual environment
python -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt
```

> Note: `sentence-transformers` pulls in `torch`. On the first install this
> can take a few minutes depending on your connection. If you're on a machine
> without a GPU, the CPU-only build of torch works fine for this project's scale.

---

## 4. Running the server

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

- `--reload` is optional and only useful during local development.
- On startup, the server will:
  1. Load the `paraphrase-multilingual-MiniLM-L12-v2` sentence-transformer model.
  2. Read `data/claims.json`.
  3. Precompute and cache embeddings (English + Hindi) for every claim in memory.
- This startup step takes a few seconds to ~1 minute depending on your machine
  the first time (model download), and is much faster on subsequent runs.

Once running, the API is available at: `http://localhost:8000`

Interactive API docs (Swagger UI) are auto-generated by FastAPI at:
`http://localhost:8000/docs`

### Configuring the similarity threshold

The match threshold defaults to `0.72` and can be overridden with an
environment variable, without touching the code:

```bash
SIMILARITY_THRESHOLD=0.68 uvicorn main:app --host 0.0.0.0 --port 8000
```

## 5. API Contract

CORS is enabled for all origins, so any frontend (web app, mobile webview,
browser extension, etc.) can call this API directly.

### `GET /api/health`

Basic health/readiness check. Useful to confirm the claims database and
model finished loading.

**Response `200 OK`:**
```json
{
  "status": "ok",
  "claims_loaded": 24,
  "model_name": "paraphrase-multilingual-MiniLM-L12-v2",
  "similarity_threshold": 0.72
}
```

---

### `POST /api/verify`

Verifies a forwarded message against the curated claims database.

**Request body:**
```json
{
  "text": "Drinking hot water with lemon cures cancer, please forward to everyone!"
}
```

| Field  | Type   | Required | Notes                                             |
|--------|--------|----------|----------------------------------------------------|
| `text` | string | yes      | 1–5000 characters. English, Hindi, or a mix of both. |

**Response — when a confident match is found (`matched: true`), `200 OK`:**
```json
{
  "matched": true,
  "verdict": "False",
  "explanation": "There is no scientific evidence that lemon water cures cancer or any form of it. Cancer treatment requires proper medical diagnosis and care, not home remedies.",
  "source_url": "https://www.cancer.gov/about-cancer/causes-prevention/myths",
  "category": "health",
  "confidence": 0.8834,
  "matched_claim_id": 1,
  "matched_claim_text": "Drinking hot water with lemon every morning cures cancer."
}
```

| Field                | Type    | Notes                                                          |
|-----------------------|---------|------------------------------------------------------------------|
| `matched`              | boolean | Always `true` in this shape.                                     |
| `verdict`               | string  | One of `"True"`, `"False"`, `"Misleading"`, `"Unverified"`.        |
| `explanation`            | string  | 2-sentence, plain-language explanation.                          |
| `source_url`              | string  | Link to a credible source for further reading.                   |
| `category`                | string  | One of `"health"`, `"financial"`, `"communal"`.                    |
| `confidence`               | number  | Cosine similarity score (0–1) of the best match.                  |
| `matched_claim_id`           | number  | ID of the matched claim in the database.                          |
| `matched_claim_text`          | string  | The English text of the matched claim, for display/debugging.      |

**Response — when no confident match is found (`matched: false`), `200 OK`:**
```json
{
  "matched": false,
  "checklist": [
    "Check the sender: is this from someone you personally know and trust, or an unknown/forwarded chain?",
    "Search the exact claim in quotes on Google to see if fact-checkers have already covered it.",
    "Check the date: old news or old photos/videos are often recirculated as if they're current.",
    "Look for a credible, named source (news outlet, government site, official body) — not just 'someone shared it'.",
    "Reverse-image or reverse-video search any photos or videos attached to the message.",
    "Be suspicious of urgent calls to action like 'forward to 10 people' or 'share before it's deleted'.",
    "Check official websites (e.g. RBI, WHO, PIB, ECI) directly for claims about money, health, or government schemes.",
    "If in doubt, don't forward it until you've verified it independently."
  ],
  "message": "We couldn't confidently match this to a known claim in our database. Use the checklist below to verify it yourself before believing or forwarding it.",
  "best_guess_confidence": 0.41
}
```

| Field                    | Type          | Notes                                                                |
|---------------------------|---------------|-------------------------------------------------------------------------|
| `matched`                   | boolean       | Always `false` in this shape.                                          |
| `checklist`                   | string[]      | Generic self-verification steps for the user to follow.                 |
| `message`                       | string        | Human-readable summary of what happened.                                |
| `best_guess_confidence`           | number\|null  | Highest similarity score found even though it fell below the threshold. |

**Error responses:**
- `422 Unprocessable Entity` — if the request body fails schema validation (e.g. missing `text` field, or `text` is an empty string).
- `400 Bad Request` — if `text` is whitespace-only (passes schema validation but has no real content).
- `503 Service Unavailable` — if called before the server finishes its startup loading step.

## 7. Extending the claims database

Add new entries to `data/claims.json` following the existing schema:

```json
{
  "id": 25,
  "claim_text": "English claim text",
  "claim_text_hi": "हिंदी में दावा",
  "verdict": "False",
  "explanation": "Two-sentence plain-language explanation.",
  "source_url": "https://example.com/source",
  "category": "health"
}
```

`category` must be one of: `health`, `financial`, `communal`.
`verdict` must be one of: `True`, `False`, `Misleading`, `Unverified`.

Restart the server after editing `claims.json` — embeddings are recomputed
automatically on every startup, so no manual re-indexing step is needed.

## 8. Notes on the matching approach

- Model: `paraphrase-multilingual-MiniLM-L12-v2` (via `sentence-transformers`),
  chosen for solid English + Hindi coverage in a shared embedding space.
- Each claim is embedded in **both** English and Hindi at startup; an
  incoming message is compared against both versions of every claim, and
  the higher of the two similarity scores wins. This improves matching for
  Hindi, English, and mixed-language ("Hinglish") forwards.
- Similarity is cosine similarity between L2-normalized embeddings
  (equivalent to a dot product), computed with NumPy.
- The default threshold of `0.72` is a reasonable starting point but should
  be tuned empirically against real forwarded messages — see the
  `SIMILARITY_THRESHOLD` environment variable above.
